### 核心发现

- 在[此前](https://www.anthropic.com/research/measuring-agent-autonomy)[研究](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic)的基础上，我们基于对 2025 年 10 月至 2026 年 4 月间约 40 万次 Claude Code 会话所做的[隐私保护分析](https://www.anthropic.com/research/clio)，提出了一套研究交互式智能体编程（agentic coding）的框架。我们评估了任务构成、人机协作方式与成功率。
- 在一次典型会话中，规划层面的决策（做什么）大多由人做出，执行层面的决策（怎么做）则大多由 Claude 做出。使用者在会话中带入的领域专长越多，Claude 每条指令所完成的工作就越多。在编程任务上，各类主要职业的成功率平均而言几乎与软件工程师相当——所谓成功，即完成了用户想要达成的事，并有测试通过或代码提交等可核验证据。
- 使用者的领域专长越深厚，会话以成功收尾的比例就越高——不过中级用户与专家用户之间的差距并不大。在我们观察的七个月里，用于调试的会话占比下降了近一半，使用方式则转向更端到端的智能体用法：部署和运行代码、分析数据、撰写非代码类文档。
- 在这七个月里，我们通过与自由职业平台的招聘信息对比估算出，典型任务的价值在几乎所有工作类型中都有所上升，平均涨幅约 25%。

## 引言

智能体编程已迅速普及。自 2025 年末以来，GitHub 上有编程智能体活动的项目占比翻了一倍以上，[^1] Claude Code 用户目前平均每周使用该工具 20 小时。[^2] 没有受过正规编程训练的人，能否成功指挥智能体完成复杂的技术工作？这类工具的快速普及与能力演进，又会对更广泛的知识工作意味着什么？这些问题目前还没有完整答案，但我们希望从 Claude Code 的使用数据中寻找早期信号。

本报告基于对 2025 年 10 月至 2026 年 4 月间约 23.5 万人产生的约 40 万次交互式会话所做的[隐私保护分析](https://www.anthropic.com/research/clio)，为 Claude Code 的实际使用方式提供实证依据。它延续了此前聚焦 Claude Code 会话中[自主性度量](https://www.anthropic.com/research/measuring-agent-autonomy)以及[Claude Code 如何改变 Anthropic 内部工作方式](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic)的研究。[^3] 在此，我们提出一套框架来描述交互式 AI 编程助手的使用情况：做的是什么工作、由谁来做、是否成功。我们关注的是通过命令行界面（CLI）、[Claude.ai](http://claude.ai/redirect/website.v1.eee555f4-5e07-4b13-b59d-5fe84452bfb0) 或 Claude Code 桌面应用产生的使用。[^4] 通过追踪模型能力增强时智能体编程用法的变化，我们可以更好地理解这些工具将如何影响编程从业者与知识工作者的劳动力市场。

随着智能体逐步嵌入非编程类工作，Claude Code 上发生的一切或许正是知识工作未来走向的预演。我们发现，Claude 正在处理更复杂、也更有价值的任务。与此同时，智能体编程中的分工依然清晰：人决定要做什么，智能体决定怎么做。

我们还发现，放大工具使用成效的是领域专长，而非编程熟练度。具体而言，领域专家成功得更频繁，也更容易从错误和误解中恢复。不过，专家与中级用户之间的差距并不大——这说明，只要对某个领域足够熟练，使用工具的效果就几乎能追上造诣深厚的人。

这些发现让我们得以初步窥见劳动力市场可能出现的转变。在我们的数据中，决定成败的是一个人对所要解决问题的理解程度，而不是他是否受过编程训练。如果这些规律在整个经济体中同样成立，那就意味着：智能体编程工具或许正在承接一部分重实现的工作，但同时也在奖赏那些对工作中所遇问题有扎实理解的人。编程智能体并未替代领域专长——工作者带给智能体的理解越充分，智能体所能完成的高质量工作就越多。

## 分工

### 人们用 Claude Code 做什么

为了解人们用 Claude Code 做什么，我们把每次会话归入九种工作模式之一——即最能概括该会话目标的那一项活动。[^5] 其中四种直接涉及编写或维护代码：*构建*新功能、*修复*故障、*测试*代码，以及*编排*其他智能体或自动化流水线。另一类是*操作*软件——部署、配置、运行流水线、监控系统。有两类更偏重于想清楚该做什么：*理解*既有系统的运作方式，以及动手前对改动做*规划*。还有两类执行的是与代码无关的操作，或者代码只是最终成果中的附带部分：*分析*数据，以及通过演示文稿和其他文字类文档进行*沟通*。

约 56% 的会话属于编写代码（25%）、修复代码（26%）或测试与编排代码（5%）。操作软件占 17%，14% 的会话是规划或探索，另有 13% 产出分析或文字材料（图 1）。

![](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2Fb0c229bb9765b65716dfdf1cd0bedc2713037288-1920x1080.png&w=3840&q=75)

九种工作模式：每次交互式会话都被归入最能概括其目标的单一模式。

我们先让模型读取会话记录来对每次会话分类，再借助隐私保护分析工具，将分类结果与每次会话自动记录的遥测数据交叉核对，其中包括是否有代码行被新增或删除。两个来源高度一致——例如，被分类器标记为创建或修改代码的会话中，超过 90% 在遥测数据里确有代码改动。详见[附录](https://www-cdn.anthropic.com/files/4zrzovbb/website/a94728142a45694292336165947f8d6e3e1a357e.pdf)。

### 谁来决定什么

Claude Code 的自主程度有多高？能力评测显示，其上限很高且仍在上升：在 [METR 的时间跨度评测](https://metr.org/time-horizons/)等基准上，前沿模型如今已能自主完成人类需要数小时才能做完的软件任务，并一路自行排除障碍。但实际使用究竟是什么样子？这里我们考察真实会话中，人与 Claude 各自承担了多少引导工作。

我们从两个角度研究这个问题：一是人们把多少*决策*交给了 Claude，二是把多少*操作*交给了它。为弄清会话中的决策分工，我们基于会话内容构建了一个隐私保护的决策归属分类器：先让分类器列出会话中所有有意义的决策，再将这些决策分为规划类（做什么、采用哪种思路、什么算完成）和执行类（改哪些文件、写什么代码、用什么语言写、运行哪些命令），最后由分类器把每项决策归给 Claude 或用户，从而给每次会话得出两个数值：用户所占的规划决策比例与执行决策比例。

平均来看，约 70% 的规划决策由人做出，而执行决策中由人做出的仅约 20%（图 2）。在实践中，智能体编程的分工十分清晰：人决定要做什么，智能体决定怎么做。

要理解会话中操作是如何委派的，我们看的是会话结构而非内容。一次 Claude Code 会话，就是 Claude 与用户之间来回交替：用户给出指令（prompt），Claude 执行操作——用户写一条指令，Claude 便去完成一些工作，随后用户再写一条指令，如此往复。一次典型会话大约有四个这样的轮次。在 10 月至 4 月的历史数据中，用户每发出一条指令，平均会触发 Claude 执行约 10 个操作的链条，有时甚至超过 100 个。[^6] 每一轮里，Claude 会读取文件、编辑代码、运行命令，并平均输出 2,400 词的文本。

在用户两次介入之间 Claude 做多少事，大体上取决于决策权在谁手里。当用户牢牢掌控执行环节（即做出 80% 以上的执行决策）时，Claude 每轮执行的操作较少（约 8 个）；而当 Claude 主导规划（即做出 80% 以上的规划决策）时，它承担的操作数量最多（约 16 个）。

![](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2Fc8c039a010b96ad191a3a9b7dfe6ad01adb410bf-1920x1080.png&w=3840&q=75)

Claude 在规划与执行决策中所占的比例：各会话中，归给 Claude 而非用户的规划决策（做什么）与执行决策（怎么做）占比的分布。在典型会话中，用户做出约 70% 的规划决策，而 Claude 做出约 80% 的执行决策。

### 专业水平

针对每份会话记录，Claude 会按五级量表（从新手到专家）评定用户在这项任务上表现出的专业水平。专业水平分类器关注三类信号：用户表述指令的精确程度、要求 Claude 核验什么，以及究竟是用户更常纠正 Claude，还是 Claude 更常纠正用户。需要说明的是，这里衡量的专业水平与职位头衔或一般能力截然不同，关键在于它是*针对具体任务*的。一位资深工程师第一次提 Rust 问题时，在 Rust 上就是新手；一位从未用过 Python 的会计，若能准确告诉 Claude 某个 Python 脚本必须执行哪些对账规则，并发现脚本在月末结账时处理错的边界情况，那么他在这项任务上就是专家。

下表展示了我们在分类器中如何界定每一级专业水平，并附上来自编程智能体会话公开数据集 [SWE-chat](https://huggingface.co/datasets/SALT-NLP/SWE-chat) 的示例请求。被归为「新手」的那段对话给出的是笼统指令，看不出任何领域知识；而被归为「专家」的对话则体现出对代码库和技术环境的深入了解。

我们量化了专业水平与 Claude 每条指令所对应的产出、操作量之间的关系。在典型的新手会话中，每条指令大约触发 5 个 Claude 操作和约 600 词的输出；专家会话触发的操作链则长出一倍以上（12 个操作），输出量达到五倍（3,200 词）（图 3）。新手与专家会话之间的这一差距，在每一种工作类型和每一个任务价值区间内都存在。

这些指标与我们在[此前关于 Claude Code 的报告](https://www.anthropic.com/research/measuring-agent-autonomy)中使用的自主性指标互为补充：后者追踪的是智能体连续运行多久、用户多频繁地自动批准其操作。相比之下，我们的决策归属指标刻画的是整场会话中实质决策由谁做出，而每条指令对应的输出量与操作数，衡量的则是人的一条指令能引出 Claude 多少自主活动。

用户越专业，Claude 每条指令做得越多：对专业水平更高的用户，Claude 每条指令产生的操作（左柱）和文本输出（右柱）都更多。箱体表示四分位距（以中位数分隔），须线表示第 5 至第 95 百分位，白点为几何平均数。两条上升趋势均具有统计显著性（p < 0.001），相邻等级之间的每一步也显著；在控制工作模式、任务价值、月份、职业和模型系列、并按用户聚类标准误的回归中，这一显著性依然成立（每提升一级专业水平，操作 +9%、输出 +13%）。

## 谁在用 Claude Code，用来做什么

### 使用者

为了解是哪些人在做这些工作，我们根据会话记录推断每位用户的职业，并映射到美国劳工统计局标准职业分类（SOC）体系的 23 个大类之一。分类器被明确要求只依据这类信号：会话开始时智能体加载的项目上下文、文件的名称与结构、用户提到的各类材料（如法律文书、临床数据、财务报告、课程大纲等）以及所用词汇。[^7] 同时明确要求它*不得*把「正在写代码」这一行为当作从事编程职业的证据。只有当明确迹象表明软件或数据工作就是用户的本职时，会话才会被归入编程类 SOC 代码（计算机与数学职业）。如果一位律师写了个脚本，用来自动标出一个文件夹里所有合同中缺失的条款，即便该会话的工作主要是软件，也会被归入法律职业。若没有任何关于用户职业的信号，则该会话不作分类。

我们能为约 70% 的会话推断出职业。在这部分会话中，涵盖大多数软件相关岗位的「计算机与数学职业」毫无意外是最大群体。紧随其后的是「商业与金融运营」、「艺术、设计与媒体」、「管理」以及「生命、物理与社会科学」。样本中增长最快的非软件职业大类则是管理、销售和法律。

### 工作内容

2025 年 10 月至 2026 年 4 月间，人们用 Claude Code 完成的工作构成发生了显著变化。最明显的一点是，用于修复故障代码的会话占比从 33% 降至 19%（图 4）。取而代之的是代码周边工作的占比上升：操作软件从 14% 增至 21%，撰写文档与数据分析则大致翻倍，从约 10% 增至 20%。

任务本身也变得更有价值。我们以「这些工作放到自由职业平台上要花多少钱」来近似估算每次会话的经济价值，并用真实招聘信息的公开数据集作校准。按这一口径，10 月至 4 月间，平均每次会话的估值上升了 27%，且这一升幅在多种工作类型中都成立。构建、操作和修复类任务的价值都增长了约三分之一甚至更多（分别约为 43%、34% 和 32%）。这些价格估算较为粗糙，因此我们主要用它来比较不同时点上的任务相对高低，而不把它当作可按字面理解的美元金额。[^8] 任务估值器的构建细节见[附录](https://www-cdn.anthropic.com/files/4zrzovbb/website/a94728142a45694292336165947f8d6e3e1a357e.pdf)。

Claude Code 工作内容的构成与价值，2025 年 10 月至 2026 年 4 月：七个月窗口期内各工作模式的会话占比。修复故障代码的会话占比从 33% 降至 19%，而操作软件、分析数据和撰写文档则有所增长。

## 成功取决于用户带来什么

任务估值是理解 Claude Code 如何帮助人们工作的一种角度，另一种角度是看有多少会话取得了成功、以及哪些会话特征与成功相关。在我们所有的成功指标上，都呈现出同一条清晰的规律：一个人在会话中表现出的专业水平越高，成功的可能性就越大。而且收益主要集中在专业水平量表的低端——新手会话与中级会话之间的差距，大于中级与专家之间的差距。

在讨论成功会话的特征之前，需要先说清我们如何衡量成功。我们观察不到用户在现实世界中的结果，也无法直接询问他们是否从 Claude 那里得到了想要的东西。因此，我们采用两项互为补充、基于会话记录的指标。第一项是*判定成功*，由一个读取完整会话记录的分类器判定用户是否完成了原本想做的事（选项为：成功、部分成功、失败、目标不明确）。随后由两个配套分类器评估支撑该判定的证据强度，以确定*已验证成功*。其中一个「成功信号分类器」专门寻找可核验的成功证据：尤其是与工作相匹配的 git 活动（如提交和拉取请求）、测试套件通过，以及用户明确的肯定。它按「无信号」到「弱信号」（1）再到「多个确凿信号」（5）为会话打分。与之并行的「失败信号」则对出问题的证据打分——报错、测试失败、反复重试、用户对输出提出异议。*已验证成功*要求*同时*满足两点：会话被判定为成功，且至少存在一个确凿的可核验成功信号。下文的分析聚焦于会话成功或失败的程度，因此排除了被归为「目标不明确」的会话，这类会话约占全样本的 7.7%。

## 专业水平带来的回报

那么，什么样的会话最容易成功？结果表明，前文所述的会话专业水平评级，对会话能否成功影响很大。

有人可能会担心，专业水平并非真正的驱动因素——也许专家只是选了不同的任务，或在其他方面有所不同。本节通过比较「同类工作、相同估值、同一月份、同一主题、来自同一职业大类」的会话，部分回应了这一疑虑，并考察结果如何随用户专业水平评级而变化。

![](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F54cae744dadf523561ef80b448161fef13991420-1850x1487.png&w=3840&q=75)

由分类器得出的成功与失败定义：示例对智能体编程交互公开数据集 SWE-chat 中经分类器标注的真实会话做了改写与概括。

在我们所有的成功指标上，一个人在会话中表现出的专业水平越高，会话成功的可能性就越大。被评为新手的会话，有 15% 达到我们最严格的*已验证成功*，77% 至少达到部分成功；被评为中级及以上的会话，达到已验证成功的比例为 28-33%，部分成功为 91-92%（图 5）。

在每一项指标上，收益主要来自从新手迈向中级这一段；中级与专家之间，斜率明显放缓。图 5 背后的回归细节见[附录](https://www-cdn.anthropic.com/files/4zrzovbb/website/a94728142a45694292336165947f8d6e3e1a357e.pdf)。

![](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F140578bc2523d4945c016d72e69628d2692228c8-1920x1080.png&w=3840&q=75)

专业水平与会话结局：按用户在任务上被评定的专业水平（从新手到专家的五级量表）划分的会话结果。左图包含全部会话；中图和右图仅保留「遇到麻烦」（失败信号 > 3）的会话，展示其中最终仍归入各种成功与失败定义的比例。每个点都是调整后的比率——我们只比较工作模式、任务价值区间、月份、任务主题与用户类型（是否为软件相关职业）均相同的会话，以此估计不同专业水平之间的差异。这些点背后的回归细节见附录。须线为样本均值的置信区间（多数小到在图中看不出来）。这些图排除了被成功结果分类器判定为「目标不明确」的会话。

在过程中遭遇挑战的会话里，也呈现出类似的梯度。当失败信号记录到确凿的失败证据时，我们就称该会话*遇到麻烦*：可能是报错、测试失败、对同一件事反复尝试，或用户表达出沮丧与不满。在遇到麻烦的会话中，计入上述所有控制变量后，已验证成功的比例从新手会话的 4% 升至专家会话的 15%（图 5）。若采用更宽松的口径，至少部分成功的比例在新手会话中为 60%，在中级到专家会话中为 80-81%。

我们也考察了反向关系——专业水平与各类失败指标的关系。注意，在这部分分析中，被判定为失败的会话指的是连部分成功都未达到的会话。若一个出问题的会话被判为失败*且*一行代码都没写出来，我们就称它被*放弃*：用户表现为新手的会话中有 19% 以放弃告终，其他用户仅为 5-7%。换句话说，经验最少的用户在苦于拿不到想要的结果时，更容易选择放弃。专业水平的价值，有一部分似乎就在于能把智能体引向正确的方向。[^9]

### 职业的影响或许不及专业水平

软件相关职业的从业者，总体上约 30% 的会话达到已验证成功；其他职业的用户这一比例约为 26%。在产出代码的会话（即至少新增或修改一行代码的会话）中，两个数字分别为 34% 和 29%（图 6）。若采用更宽松的成功定义，软件相关职业与其他职业之间的差距会收窄——在产出代码的会话中，两组至少达到部分成功的比例分别为 89% 和 88%。这 5 个百分点的差距很小，而且即便两组成功率都在上升，七个月里它也既未扩大也未缩小。在产出代码的会话中，数据集里规模最大的十个职业，成功率与软件工程师的差距都在 7 个百分点以内。管理类职业在已验证成功上最高，略高于软件工程类职业。他们较高的已验证成功率，或许反映了管理技能可以迁移到指挥智能体上；但也可能部分源于我们的测量方式：验证在一定程度上依赖会话记录中的明确确认，而管理者在得到所求结果时可能更愿意明说。[^10]

![](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F3d2d5df2002152c1a010a139deadab4a7e593a39-1920x1080.png&w=3840&q=75)

按推断职业划分的编程会话中已验证成功与判定成功的比例：在至少新增或改动一行代码的会话里，按用户被推断的职业大类划分，十个最大群体中满足严格成功定义——判定成功与已验证成功——的会话占比。每个群体与软件／数学类用户（SOC 代码「计算机与数学职业」）的差距都在 7 个百分点以内。误差线为按不同账户计算的 95% 置信区间。

## 展望

本报告的结果初步勾勒出这样一幅图景：智能体编程放大了某些类型的知识与技能，同时替代了另一些。在产出代码的会话中，各大职业的成功率与软件相关职业相差不过几个百分点。看起来，编程智能体正在让「编程背景」对能否写好程序变得不那么重要。

与此同时，成功的会话往往更能体现领域专长。被评为专家的会话达到已验证成功的比例，是新手会话的两倍多；而一旦会话遇到麻烦，新手放弃会话的比例是其他人的数倍。协作的形态让这幅图景更具体：领域专家每给出一条指令，都能让 Claude 完成更多工作。因此，把 Claude 引向成功的能力，更多来自对某个领域的掌握，而非写代码的能力。如今，无论身处哪个领域，具备这种掌握力的人都可能完成过去做不了的技术工作；而完全不具备这类专长的人，从同一工具中获得的收益要少得多。况且收益主要来自「够用」而非「精通」——对领域有实操层面的把握就已拿到大部分好处，深度专精在此之上只多添了一点点。

这些发现仍是初步的。与我们的多数研究一样，我们无法衡量现实世界中的结果，比如某次会话写出的代码此后究竟被采用还是弃用，又是否产出了有经济价值的成果。此外，本报告排除在外的非交互式用法，在全部活动中占了相当大一块；建立衡量它的框架是后续工作的优先事项。而我们对会话的所有分类，都依赖模型对会话记录的解读。在[附录](https://www-cdn.anthropic.com/files/4zrzovbb/website/a94728142a45694292336165947f8d6e3e1a357e.pdf)中，我们说明了分类器与独立遥测数据在预期方向上一致，并在多数会话上与一个强参考模型达成共识。但分类器的大规模验证依然困难，Claude Code 会话又额外增加了难度——它们可能过于冗长复杂，以致人工标注难以充当真值。

随着模型、用户以及二者之间的分工不断变化，本报告描绘的图景也会被更新。我们希望这些指标能让我们及时追踪到那些影响深远的转变。例如，若专业水平带来的回报开始随时间下降，那就意味着模型正开始提供目前由用户贡献的关键判断，而这些工具的收益也正在向领域专家之外的人群扩散。若非软件职业用户成功完成的编程会话占比持续增长，则可能表明软件生产正在变成各行各业日常工作的一部分，而不再是某一单一职业的产物。这些转变会改变谁从智能体编程中受益、受益多少，也会影响劳动力市场最看重什么。
