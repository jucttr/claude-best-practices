# Obsidian Markdown 编辑规范

只约束一件事：**改动已有的 Obsidian 笔记**。目标是让用户点名的改动生效，其余一切保持原样。
本规范只写编辑约束与 Obsidian 特有写法，不解释 Markdown 基础语法。

## 一、适用场景与触发条件

| 维度 | 命中 | 不命中 |
| --- | --- | --- |
| 对象 | 已存在的 `.md` 笔记 | 从零新建的文档、代码与非笔记文件 |
| 动作 | 新增、追加、修改、更新、删除段落或条目；改标题文字与层级；更新 frontmatter 字段值；增删标签、双链、附件引用；调整版式 | 全文重写、整体重排、批量格式转换 |
| 典型说法 | 「把这段补进去」「这段删掉」「日期改成 X」「补个双链」「整理下排版」「加个 note」 | 「写一篇新笔记」「转成 HTML」「给 GitHub 用」 |

用户明确要求「重写 / 全文重构」时，第二节的内容最小改动规则失效，但第三、四节的链接、元数据、附件与组织约束仍然生效。

## 二、必须遵守的编辑规则

1. **先区分两类指令，再定改动范围。**
   - 点名改内容（改写句子、换数字、增删段落）：照改，且不外溢到相邻段落。
   - 只点名改版式（加 callout、调图片大小、重排列表）：只动容器与呈现，论点、数字、原话、锚点一字不改。
2. **先读后改。** 编辑前完整读取目标文件，并抽看同目录 1–2 篇笔记的 frontmatter 字段、标签层级与命名习惯。目标文件已有写法优先于任何通则；两者冲突时沿用目标文件。
3. **不擅自重构。** 不重排章节、不合并或拆分段落、不改未点名的标题文字与层级、不统一全篇标点 / 空行 / 缩进 / 列表符号。
4. **删除前查引用。** 删除段落、标题或块之前，检查是否有 `[[笔记#标题]]`、`[[笔记#^block-id]]` 指向它；有则先告知用户并等确认，不静默删除。改标题文字同理——要么同步更新所有指向它的链接，要么改为不改标题。
5. **不动其他文件。** 被双链引用的笔记、附件文件、目录结构都不在改动范围内。
6. **验证跟在动作后。** 每次编辑完按第五节逐项核对，未通过项先修再交付。

## 三、必须保留的 Obsidian 兼容写法

### 元数据（YAML frontmatter）

- `---` 必须是文件第一行；不得后移、删除，或换成 `+++`。
- 字段集合与顺序原样保留；`tags` / `aliases` 保持列表式（`- 值`），不改成 `tags: [a, b]` 或逗号串；未点名时不新增字段。
- 更新日期类字段只改值，不改字段名与日期格式；值含 `:` `#` `|` `>` 时加引号。
- 验证：仍是文件第一段、YAML 可解析、字段数与原文件一致（点名增删的除外）。

### 内部链接

- 保留 `[[...]]`，不改成 `[文字](路径.md)`、不补 `.md` 后缀；别名 `|别名` 原样保留。
- 带路径双链以 vault 根为基准（如 `[[docs/settings_README|settings_README]]`）；跨文档引用才用双链，文件路径作为「路径」提及时用行内代码。
- 指向标题与块的 `[[笔记#标题]]`、`[[笔记#^block-id]]` 原样保留。
- 验证：`[[` 数量、目标、别名与改前一致（点名增删的除外），所有链接仍可解析。

### 标签

- YAML `tags` 保持列表式；正文 `#AI学习/skill` 这类层级标签保留 `/`，不拆成平级标签、不改大小写与命名。
- 不擅自新增、改名、合并或删除标签；代码块与行内代码里形似标签的文本不当作标签处理。
- 验证：改动前后的标签集合逐个可对应。

### 附件引用

- 保留 `![[文件名.png]]`，不改成 `![](path)`；不移动、不重命名附件文件。
- 只调显示尺寸时用 `![[a.jpg|300]]`（宽）或 `![[a.jpg|300x400]]`（宽×高），原图不动，不用 HTML 图片标签。
- 多图横排写在同一行、空格隔开。
- **表格单元格里的 `|` 必须写成 `\|`；callout 与正文里不能转义**，否则链接失效。
- 验证：每个 `![[` 目标文件仍存在；表格内的 `\|` 没被当成列分隔符，正文与 callout 里的 `|` 没被误转义。

### 笔记组织一致性

- 不重命名、不移动文件、不改所在目录；新增内容沿用目标文件已有的标题层级、列表符号、表格对齐方式与 callout 类型，不引入该文件没用过的容器。
- callout 保持 `> [!note]` 形式（可带标题、可折叠 `+` / `-`），不降级成普通引用 `>`。
- Mermaid 代码块保留 `mermaid` 语言标记；任务列表保留 `- [ ]` / `- [x]`，不改成普通列表。
- 验证：新增段落的容器类型都能在同文件找到先例；跨文档引用仍以 vault 根为基准。

## 四、禁止的无关改动

- 不重写未点名的论点、结论、数字、引用原话、锚点。
- 不「顺手」统一标点、空格、空行、缩进、换行风格，不批量替换术语。
- 不「顺手」修错别字、病句、失效链接或补标签，除非用户点名，或不修会破坏 Obsidian 解析。
- 不把 wiki 语法「现代化」成标准 Markdown，也不引入 Obsidian 之外的语法、HTML 标签、外部工具或转换脚本。
- 不删除未点名的内容，包括看似冗余的 callout、注释、待办项。
- 不新建文件、不改动其他笔记与附件、不在交付时附带未要求的说明文档。

## 五、验收标准（逐项可检查）

改动前后逐行比对，下列每一项都必须通过：

- [ ] **范围**：只有用户点名的行发生变化；未点名段落逐字一致。
- [ ] **元数据**：`---` 仍在第一行；YAML 可解析；字段集合、顺序、列表式写法未变（点名增删的除外）。
- [ ] **链接**：`[[` 数量、目标、别名与改前一致；指向被改标题的链接已同步；表格内 `|` 已转义为 `\|`，正文与 callout 内未转义。
- [ ] **标签**：YAML `tags` 与正文 `#标签` 未增删改名，层级 `/` 保留。
- [ ] **附件**：每个 `![[` 目标仍存在、路径未变；尺寸参数只用 `|宽` / `|宽x高`。
- [ ] **容器**：callout、Mermaid、任务列表、表格对齐沿用原文件；未出现新容器或非 Obsidian 语法。
- [ ] **组织**：文件路径、文件名、目录未变；未产生新文件；跨文档引用以 vault 根为基准。
- [ ] **内容**：版式类改动下，论点、数字、原话、锚点逐字未改；无「顺手优化」的改写痕迹。

## 六、正误对照

**1. 只加标注，别改正文**（用户说「这段加个 note 标注」）
- ✗ 顺手把整段改通顺，再包进 callout
- ✓ 段落一字不动，只在其上方插入 `> [!note] 待核对`

**2. 双链不降级**（用户说「补个双链」）
- ✗ `[settings_README](docs/settings_README.md)`
- ✓ `[[docs/settings_README|settings_README]]`

**3. 表格内嵌图要转义**（用户说「表格里放张图，宽度 300」）
- ✗ `| ![[a.png|300]] |`
- ✓ `| ![[a.png\|300]] |`

**4. 正文嵌图不转义**（用户说「正文那张图宽 300」）
- ✗ `![[a.png\|300]]`
- ✓ `![[a.png|300]]`

**5. 标签保持列表式**（用户说「tags 里加个标签」）
- ✗ 改成 `tags: [AI学习/skill, 笔记]`
- ✓ 在原有列表里追加一行 `- 笔记`

**6. 不外溢到别处**（用户说「第三节日期改成 2026-11-08」）
- ✗ 同时统一全文标点、补三个标签、删掉一个旧 callout
- ✓ 只改那一个日期值
