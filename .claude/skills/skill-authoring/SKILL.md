# Skill 编写规范（Claude Code）

一份给已经很聪明的助手看的补充说明。每次写 skill 前读一遍，写完按文末清单自检。

## 一、它是什么

一个**包含一个 `SKILL.md` 文件的文件夹**。没有注册中心、没有构建步骤、没有 SDK。
最小可用版本只有两行 frontmatter 加几行正文——本文件自己就是这么写的。

它解决的唯一问题是：**常驻的内容和按需的内容从来没被切开过**。
`CLAUDE.md` 每次对话全量加载；skill 只在命中时加载正文，元数据常驻。

## 二、参考型还是任务型

判据只有一条：**你希不希望 Claude 自作主张启动它。**

|      | 参考内容              | 任务内容                             |
| ---- | ----------------- | -------------------------------- |
| 装什么  | 约定、模式、风格、领域知识     | 部署、提交、生成这类分步动作                   |
| 谁触发  | 隐式，Claude 判断相关就生效 | 显式 `/name`                       |
| 典型开关 | 默认                | `disable-model-invocation: true` |

风格规范你希望它自动生效，生产部署你不希望——Claude 不该因为代码看起来好了就决定上线。

## 三、Frontmatter：两层口径，别混着说

这是最容易写错的地方。**开放标准和 Claude Code 是两层，字段集不同，混着引用会互相打架。**

**规范层六字段**（通往 claude.ai 上传 / Skills API / 打包的路径**只允许这六个**）：
`name`、`description`、`license`、`compatibility`、`metadata`、`allowed-tools`。
含其他字段会**硬报错**：`Unexpected key(s) in SKILL.md frontmatter: ...`

**Claude Code 扩展字段**（只在本地生效）：`when_to_use`、`argument-hint`、`arguments`、
`disable-model-invocation`、`user-invocable`、`disallowed-tools`、`model`、`effort`、
`context`、`agent`、`background`、`hooks`、`paths`、`shell`。

### 字段约束

- `name`：可选，**省略则用目录名**。1–64 字符，小写字母数字连字符。
  不能含 `<`、`>`、XML 标签、零宽/控制字符、方向改变字符、非常规空白。
  保留名：文件夹不可叫 `synced`；`anthropic-skills` 命名空间保留。
  （API 路径额外禁止 `anthropic`、`claude` 两个保留字。）
- `description`：**推荐字段**，触发质量几乎全压在这一个上。省略时回退到正文第一个非空行。
- `description` + `when_to_use` 合计在技能列表中**截断 1536 字符**（Claude Code）；
  API 上传路径是 **1024**。关键触发词放前面。
- `when_to_use` 是唯一用下划线的字段名，其余一律连字符。字段名拼错会被静默忽略。
- 布尔字段接受 `true/false/yes/no/on/off/1/0`（v2.1.218 之前只认 true/false）。

### 三个致命的格式坑

1. **开头的 `---` 必须是文件第一行**，否则整个文件（含 `---` 标记）都会被当正文。
2. **YAML 解析失败不会报错**——技能照常加载，但**一个字段都不生效**。
   一个 tab、一个缺失的冒号、一个未加引号的特殊字符都够。
3. 用空格缩进，不要用 tab。

### description 的三条写法

1. **用祈使句写用户意图**，不写内部实现。
   "用 flyway 约定生成迁移文件并校验" 优于 "包含 flyway 迁移模板的 skill"
2. **列出间接场景**——用户没提关键词但其实该用的说法。
   审查类 skill 的直接场景是"帮我审查这段代码"，间接场景是"这个实现合理吗""看下这个 PR"
3. **指明边界**。"处理 PostgreSQL 迁移"本身已隐含不适用于 MySQL

坏例子：`description: Helps with PDFs`——太模糊、没说做什么、没给触发场景。写坏了正文再好也不会被执行。

## 四、正文五条判据

- **只写模型不可能知道的。** 判据：删掉这一句，Claude 自己会不会做对？会，就删。
  不用解释什么是 REST API，但要说清遍历用户列表必须分页
- **它不是教程。** 是给聪明助手的补充说明，不是给新手的入门文档
- **粒度按容错率分叉。** 判据是"做错了要不要花大量时间回滚"——
  写文档给方向，数据库迁移给精确步骤，最好锁进 `scripts/`
- **给默认值，不给菜单。** 写"用 Jest 跑测试；项目本来用 Vitest 就改用 Vitest"，
  而不是列 Jest / Mocha / Vitest 让人选。列菜单等于把算力花在"选"而不是"执行"上
- **每个关键动作后面跟一个验证。** 不只说做什么，还说做完怎么确认做对了

**长度**：SKILL.md 控制在 **500 行以内**。正文加载后跨轮常驻，每一行都是反复的 token 成本。
超出部分下沉到支撑文件，并在正文写明"什么时候去读哪一份"。
写"要做什么"，不要叙述"如何/为什么"。

## 五、三个可选附件目录

| 目录 | 装什么 | 性质 |
|---|---|---|
| `scripts/` | 可执行脚本 | **被执行，内容不进上下文**，只有输出占 token |
| `references/` | 补充文档 | 被读，用到才加载 |
| `assets/` | 模板、静态资源 | 被用（按路径引用），不读进上下文 |

区别一句话：references 是被读的，assets 是被用的，scripts 是被执行的。

## 六、加载机制（决定你会不会用错）

**Discovery → Activation → Execution**：启动时只加载每个 skill 的名字和描述 → 判断相关才读全文 → 执行时按需读附件。

**代价在两端，官方文档没展开，但恰恰决定用法：**

**进的一端：元数据是常驻的，每个轮次都常驻。**

| 技能类型 | 你能调用 | Claude 能自动调用 | 上下文里有什么 |
|---|---|---|---|
| 默认 | 是 | 是 | 描述**始终在**；正文调用时才加载 |
| `disable-model-invocation: true` | 是 | 否 | **描述不在上下文**，Claude 完全看不到 |
| `user-invocable: false` | 否 | 是 | 描述始终在；正文调用时才加载 |

所以"装 100 个也不占上下文"是错的：元数据是**乘上轮次数**的常驻成本，不是一次性开销。

**出的一端：正文加载后赖着不走。**
渲染后的正文作为单条消息进入对话，**后续轮次不再重读文件**。
所以正文该写持续有效的指导，不是一次性步骤。
重复调用且渲染内容完全相同时，只插入一条"该技能已加载"的短提示，不会重复插入第二份。

**压缩预算**：上下文被总结后，每个被调用过的 skill 重新挂回最近一次调用内容，
每个截前 **5000 token**，所有 skill 共享 **25000 token** 总预算，**从最近调用的往回填**。
调用了很多 skill 时，较早的那些压缩后可能被整个丢掉。

**其他机制要点**
- `paths`：glob 限定自动激活范围，只在处理匹配文件时生效
- `allowed-tools`：预批准工具，**只在调用那一轮有效**，下一条消息即清除。
  单写 `Bash` 等于放行所有 shell 命令，应写成 `Bash(git status *)` 这种窄模式
- `context: fork`：在隔离子代理中运行，子代理看不到会话历史，**默认后台运行**。
  后台 fork 的编辑不进检查点，`/rewind` 不恢复
- 改动检测：`SKILL.md` 的新增/编辑/删除会在当前会话内被拾取，无需重启。
  但若会话开始后才**新建**顶层技能目录，需要 `/reload-skills`
- 嵌套 `.claude/skills/`（启动目录之下）不在启动时加载，首次读写该子目录时才加载

**跨平台**：格式统一 ≠ 位置统一。Claude Code 读 `.claude/skills/`，
Codex 读 `.agents/skills/`，Cursor 读 `.cursor/skills/`。
可移植的是**文件**，不是**配置**——要真跨平台得留一份权威副本，其余用符号链接。

## 七、写完自检清单

- [ ] 开头的 `---` 是文件第一行？YAML 能解析？（tab / 缺冒号 / 特殊字符未加引号）
- [ ] `name` 合法且与目录名一致？没撞保留名 `synced` / `anthropic-skills`？
- [ ] `description` 同时说清了**做什么**和**何时用**？包含间接场景说法？写明了边界？
- [ ] 只走本地的话，用了扩展字段吗？要上传的话，是不是只剩规范六字段？
- [ ] 逐句问一遍：删掉这句 Claude 会不会做对？会，就删
- [ ] 每段关键动作后面有没有跟一个验证步骤？
- [ ] 超过 500 行了吗？该下沉的是否已进 `references/` 且正文写了何时去读？
- [ ] 任务型且带副作用，要不要加 `disable-model-invocation: true`？
